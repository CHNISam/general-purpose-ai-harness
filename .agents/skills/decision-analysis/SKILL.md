# Decision Analysis

Use this skill for a **Decision Gap**.

## First remove non-options

Reject alternatives that violate mandatory constraints.

Do not spend detailed comparison effort on infeasible choices.

## Compare only decision-changing criteria

Possible general criteria:

- expected effectiveness;
- evidence quality;
- cost;
- schedule;
- uncertainty;
- reversibility;
- technical risk;
- operational risk;
- downstream consequences;
- resource demand;
- opportunity cost.

For capability-source decisions, use the criteria in the `capability-sourcing` skill instead of duplicating a generic scorecard.

Do not score every criterion mechanically.

## Preserve ownership

Do not silently substitute the executor's preference for the Outcome Owner's objective.

Do not silently accept residual risk outside delegated authority.

If priorities conflict beyond delegated authority, expose the conflict rather than inventing a trade-off policy.

## When uncertainty dominates

Prefer the cheapest action that reduces the most **decision-relevant** uncertainty.

A reversible experiment or spike may dominate an argument.

## Action selection

Prefer the smallest action with the highest useful leverage:

- close the dominant blocker;
- reduce important uncertainty;
- test or falsify a key assumption;
- acquire a required capability;
- reuse a solved capability;
- advance the intended Outcome;
- produce reusable evidence.

Balance against cost, risk, irreversibility, complexity, maintenance burden, and ownership burden.

## Exit

Once one direction is sufficiently selected:

- if dependent execution structure is unclear → `planning`;
- if a capability source is still unresolved → `capability-sourcing`;
- if an Execution Gap remains → execute;
- after action → `validation`.
